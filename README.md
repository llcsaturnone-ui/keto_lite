# Дневник питания

Готовое приложение — **index.html** в корне репозитория вместе с папкой **assets/**. React и код приложения загружаются с того же сайта: внешние CDN и Babel в браузере не нужны. Сборка также создаёт отдельный **Дневник-питания.html** для скачивания, в котором уже находятся все стили и библиотеки.

## Что изменилось

- Две вкладки: «Дневник» и «Прогресс», с общей навигацией по датам.
- В дневнике быстрый поиск по всей базе и две горизонтальные ленты: избранное и часто используемые продукты. Полный каталог доступен в настройках.
- Кнопка ☆ добавляет продукт в избранное. Частота считается по записям в дневнике.
- Можно выбрать несколько продуктов, указать вес напротив каждого и добавить их в дневник одной кнопкой. Выбор сохраняется при поиске, переключении лент и вкладок.
- При добавлении выбирается приём пищи: завтрак, обед, ужин, перекус или своё название. Продукты с одинаковой подписью за один день группируются с общим КБЖУ и КБЖУ каждой позиции. Продукт можно перенести в другой приём пищи через редактирование; целую группу — переименовать или объединить с другой.
- «＋ Продукт» прямо в дневнике: ручное заполнение или JSON/текст с сохранением одной кнопкой. По желанию новые продукты сразу выбираются для ввода граммов. Порции не попадают в дневник до подтверждения веса.
- В «Прогрессе»: вес, обхваты груди, живота, таза, шеи, бицепсов и бёдер слева/справа; проценты жира, мышц и воды; мышечная и костная масса, висцеральный жир, основной обмен и заметка.
- Все показатели необязательные. Записи можно добавлять, исправлять и удалять по датам. Данные весов вводятся вручную; медицинские оценки не рассчитываются.
- Линейные графики по группам с одинаковыми единицами, периоды 7/30/90 дней и всё время, выбор линий и просмотр значений за дату. Пропуски не превращаются в нули; горизонтальное расстояние соответствует времени между замерами.
- Для веса есть среднее по имеющимся записям за последние 7 календарных дней. График ограничен выбранной датой дневника.
- Перед сохранением проверяются все порции; ошибочный вес не приводит к частичному добавлению еды. Общий КБЖУ выбранных порций виден заранее.
- В настройках: дневные цели, все продукты, создание и редактирование, удаление, текстовый/JSON-импорт и резервная копия.
- Поиск по названию, категории, недавно добавленные и часто используемые продукты — и в дневнике, и в настройках.
- Частота считается по числу записей продукта в дневнике; удалённая запись больше не учитывается. Недавно добавленные сортируются по дате создания продукта; для старых продуктов без даты сохраняется прежний порядок.
- Дробные значения принимаются с точкой или запятой.

## Перенос существующих данных

Перед заменой старого приложения скачайте резервную копию в его настройках.

При замене страницы на **том же адресе сайта и в том же браузере** дневник читает прежние `diet_goals_v2`, `diet_foods_v2`, `diet_logs_v2`. Исходные ключи остаются неизменными. Записи удалённых разделов также не удаляются из хранилища.

Если открыть приложение по **другому адресу, как другой локальный файл или в другом браузере**, в настройках загрузите прежнюю резервную копию. Браузеры хранят данные отдельно для разных сайтов; перенос файла не переносит записи автоматически. Резервные копии версий 10 и 11 поддерживаются. Копия версии 12 содержит питание, избранное и все замеры. Перед восстановлением показываются количества записей и предупреждение о замене текущих данных. У прежних копий замеры и избранное пусты.

Приложение сохраняет данные локально на устройстве, без аккаунта и синхронизации между устройствами. Регулярно скачивайте резервную копию. Для стабильного хранения предпочтительно размещать файл на постоянном HTTPS-адресе. Поведение хранения при открытии `file://` зависит от браузера.

## Исходники

- `src/App.jsx` — интерфейс.
- `src/core.mjs` — проверка данных, импорт, расчёты, поиск и сортировки.
- `src/storage.mjs` — миграция и журнал изменений. Отдельные изменения записываются отдельно, чтобы вкладки не затирали весь дневник друг друга.
- `src/Progress.jsx`, `src/progress.mjs` — замеры и графики; изменения отдельных полей объединяются с текущей записью.
- `src/QuickFoods.jsx` — быстрый поиск, избранное, горизонтальные карточки.
- `src/styles.css` — мобильная тёмная тема.
- `scripts/build.mjs` — сборка одного HTML-файла.

Сборка: `pnpm install`, `pnpm build`. Проверки: `pnpm test`.

После изменения исходников выполните сборку и сохраните обновлённые `index.html`, `sw.js` и папку `assets/` вместе с исходниками. GitHub Pages публикует готовое приложение из корня ветки `main`. Иконки приложения сохранены в `icon-180.png`, `icon-192.png`, `icon-512.png`; настройки установки находятся в `manifest.webmanifest`.

Установленное приложение обновляется по прежнему адресу. Service worker запрашивает страницу из сети и хранит последнюю доступную копию для работы без подключения. Старые модули сборки сохраняются, чтобы открытые страницы продолжали работать. LocalStorage при обновлении не очищается.

Проверки: расчёты, старые и новые резервные копии, сохранение данных, одновременное добавление нескольких порций, избранное, замеры, календарные интервалы и средние на графиках, ошибки сохранения и основные пользовательские сценарии. Автоматические проверки интерфейса выполняются в JSDOM.
